# Sdd-Developer-setup

Marketplace de Claude Code con dos plugins: `sdd` (Spec-Driven Development mínimo) y `libraries` (skills de uso de librerías). Documentación en dos niveles: `README.md` para quien lo usa, `docs/IMPLEMENTACION.md` para quien lo mantiene, `docs/decisiones.md` para lo que se dejó fuera. Aquí solo lo que no se deduce del código.

- Este repo **es** el marketplace: `.claude-plugin/marketplace.json` en la raíz lista los plugins de `plugins/`. La versión de cada plugin vive en su `plugin.json` y en su entrada del marketplace y deben coincidir; subirla en los dos y mergear a `main` es publicar (la tarea diaria de cada developer la recoge). `MAJOR` si cambia el formato de `spec.md`/`delta.md`, `MINOR` si cambia una skill o se añade una, `PATCH` texto o script sin cambio de formato.
- `sdd` tiene **una sola skill** (`skills/sdd/SKILL.md`) que decide la fase por el `status` del delta; no volver a partirla en una skill por fase. Lo que lee solo a veces va en `references/`. Sin nombres de herramientas de Claude en el texto; la única dependencia del host es `${CLAUDE_PLUGIN_ROOT}` para localizar el script.
- `libraries` lleva una skill por librería (`skills/<area>-<libreria>/SKILL.md`, 30-60 líneas, descripción con las frases de uso). Reglas en `docs/IMPLEMENTACION.md`; `masstransit-saga` es el modelo. No meter ahí reglas del flujo SDD.
- `plugins/sdd/scripts/sdd.py` es la única lógica. Stdlib solo: CI lo ejecuta con `actions/setup-python` y las skills con el Python del developer. Tests: `python -I -m unittest discover -s plugins/sdd/scripts/tests`. Regla nueva del formato: primero el test.
- El bloque de un requisito en `spec.md` va desde su `### REQ-…` hasta el siguiente `###` o `##` (`split_requirements`; el último REQ se tragaba `## Decisiones` la primera vez).
- `docs/features/registro-usuario/` es ejemplo y fixture del CI propio (`sdd.py scan docs` debe dar `ok`). Su delta está en `approved` para poder probar `merge`; la prueba se deshace con `git checkout docs/ && git clean -fd docs/`.
- `sdd-checks.yml` es CI de este repo y `workflow_call` para los consumidores (`deltas` hace checkout de este repo para tener el script; `script-tests` lleva `if: github.event_name != 'workflow_call'`).
- `templates/`: `AGENTS.md` es la plantilla real y `CLAUDE.md` solo `@AGENTS.md`, para que Claude Code, Codex y Copilot lean lo mismo. Los instaladores los copian al repo si no existen; no sobrescriben.
- `setup/install.*` registran la actualización diaria (08:00 por defecto; Windows Task Scheduler, macOS LaunchAgent `com.sdd.plugin-update`, Linux crontab marcado `# claude-sdd-plugin-update`; macOS sin probar en un Mac real). `setup/update.*` actualiza el marketplace y **todos** los plugins instalados desde él (los detecta en `claude plugin list`), log en `~/.claude/sdd-update.log`, salida 1 si hay `Failed`. Los `.ps1` llevan BOM UTF-8; los `.sh` van en LF.
- Documentación en español; nombres de ficheros, skills y comandos en inglés. Sin comentarios en el código salvo el docstring de uso de `sdd.py`. Commits convencionales; autor, la identidad personal de `git config --local`.
